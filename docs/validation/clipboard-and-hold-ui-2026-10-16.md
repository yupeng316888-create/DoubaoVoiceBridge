# 2.6.4：剪贴板投递与长按说明验证

## 行为与界面

独立的远控自定义键采用长按：在 UU 中按住说话，松开结束识别并粘贴。即使豆包语音键采用单击启动，也不改变独立远控键的交互。只有显式选择“跟随豆包按键”才沿用豆包的交互方式。主窗口按当前选择生成用法，底部显示 2.6.4；按键录制、同步选项和测试入口放在默认收起的高级设置中。菜单栏只保留状态、设置、更多和退出。

投递先激活并确认原 UU 窗口，再写剪贴板并等待同步。同内容被同步程序重新发布时允许继续；不同文字替换、目标进程或窗口变化时取消。启用恢复时仅恢复本工具仍持有的剪贴板代数。新安装默认保留最新文字，已保存的恢复选项不变。

## 回归细节

修复前，同一文字重新发布会触发 `targetChanged`，实际按键发送数为 0；生产路径回归输出 `SELF_TEST_FAILURE same transcript republished during sync must still paste into unchanged UU target`。另一个回归确认原实现先写剪贴板、后激活 UU，输出 `SELF_TEST_FAILURE UU activation must precede publishing the transcript for clipboard synchronization`。

修复后，打包应用运行 `--self-test` 输出 `SELF_TEST_OK`。9 个投递场景覆盖：本工具原代数恢复、相同内容新代数、不同内容替换、目标窗口变化、目标进程退出、进程延迟激活、激活超时、原窗口延迟激活、粘贴后新复制不被延迟恢复覆盖。现有快捷键录制、持久化、监听路由、合成事件顺序和文本稳定等待自检继续执行。

“测试远端文字粘贴…”使用手动文字，不启动豆包、不录音。本机 Return 仅触发粘贴，实际发送事件为完整 Command-V；没有向远端发送 Return。UU 不提供接收确认，完成后仍需查看远端输入框。
