# 2026-09-08 实机问题与本地修复记录

基于上游提交 `2429a8fefb84c94e7fd9e3bebd79500cf68784b0` 的 Fn 实验分支。下文的 2.3.1–2.3.4 是本地构建编号，不代表上游已经发布这些版本。本次由 AI 协助修改代码，并由实际使用者验证部分设备行为。

## 场景与环境

- 控制端：Apple Silicon MacBook Air，macOS 15.7.5，UU 4.39.0，豆包输入法 0.9.7。
- 被控端：Mac mini，UU 4.38.0；目标是将控制端麦克风识别出的文字填入远端输入框。
- 关联设备：使用豆包键盘的 iPhone／iPad。
- 本地适配使用长按 Fn；上游默认长按左 Control，因此这里的观察不能直接证明未修改的上游原版存在相同故障。

## 问题、修改与证据

### 1. 间歇性提示“发送前焦点发生变化”

使用者估计约每 3–5 次出现一次，并非严格计数实验。旧代码将本地剪贴板 changeCount 变化、前台应用变化和原窗口不匹配合并成同一错误；不能由这句提示认定使用者主动切换了焦点。

实验修改：

- 将窗口变化、原窗口不可用、窗口就绪超时、剪贴板变化、同步超时分别报告。
- 使用可取消、带期限的单次发送状态机等待原 UU 进程及原 AX 窗口；原窗口匹配并持续稳定才允许发送。
- 相同的单项纯文字被同步器重新写入时，不仅凭 changeCount 改变就拒绝；读取不稳定或暂时清空时等待，文字不同或新混合类型时取消。
- macOS 14+ 使用协作式激活；AX 调用设置短超时。

结果：使用者在修复后大约试了 5 次，反馈正常。没有完成 10 次连续测试，也没有覆盖长时间网络抖动，不能称为彻底消除间歇性故障。

### 2. iPhone／iPad 豆包的复制提示反复弹回，挡住语音按钮

复现线索：在被控 Mac 复制文字后，移动端豆包复制建议关闭后又出现。停止实验工具后，使用者确认不再弹回、可以点击语音按钮。该对照支持工具参与了干扰，但不能证明旧剪贴板恢复、UU 双向同步或系统通用剪贴板中的哪一个是唯一原因。

实验修改：删除成功、失败、退出路径中的旧剪贴板回写及延迟恢复。一次听写只写入一次文字，完成后保留该文字；使用 `NSPasteboard.prepareForNewContents(with: .currentHostOnly)` 请求限制跨设备传播。

结果：重新启用修改版后，使用者确认提示能关闭且不再弹回。**行为变化：不再恢复听写之前的剪贴板。** `.currentHostOnly` 与 UU 转发的兼容性仍需独立确认，不能把它视为远端收到文字的证明。

### 3. 文字已识别出来，但自动填入远端较慢

修改前的一组日志含 13 条完整发送记录，其中最近 8 条：

- 最后一次被记录的文字更新 → 完整 Command-V 指令发送：约 1.237–1.683 秒。
- 程序判定文字稳定 → 完整 Command-V 指令发送：约 0.863–1.320 秒。

这些是本地日志时间差，不是远端实际渲染耗时；13 条日志也不等于使用者执行了 13 次规定测试。

实验修改：UU 仍保留原窗口焦点时省略重复 AX 窗口写操作；让窗口稳定检查与剪贴板同步等待重叠。识别稳定时间与同步等待配置的下限保持不变。

结果：使用者明确反馈更新后更快、可以接受。没有取得更新后的同条件量化样本，不报告提速百分比。

### 4. 偶尔粘贴出了上一次内容——未解决

使用者报告一次旧内容误粘贴，但未看清当时本地浮窗文字，确切发生时间／构建版本也未能锁定。因此还无法区分：

- 本地输入法向复用的文本框提交了旧文字；
- 本地是新文字，但远端剪贴板仍是旧文字；
- 其他同步或时序问题。

代码审查确认的限制是：当前只检查控制端剪贴板和 UU 窗口，没有被控端确认本轮文字已收到的机制。固定等待及控制端内容正确都不构成远端收件确认。增加等待时间也不能证明这个问题已解决。

本项没有修复。使用者选择暂缓追查，先解决延迟；该草稿应保持实验状态，后续需用两次明显不同的测试文本检查本地显示、被控端实际内容及迟到／乱序同步。

## Fn 适配与已有行为的边界

- Fn 适配是本次需求，不把上游默认左 Control 称为 bug。本次 UU 原生快捷键设置无法录入单独 Fn，故制作了实验分支。
- 仅在 UU 前台拦截长按 Fn；其他应用、短按和组合键保留透传。Fn 合成走本地 session tap，普通远控透传走 HID tap。
- 检查豆包和 UU 的监听顺序，包括相关的 listen-only tap，以减少重复启动；跨版本兼容性仍需实际验证。
- 完整的 Command-down / V-down / V-up / Command-up 序列、释放修饰键的收尾机制和部分听写框布局等原本已在上游提交中，不能算成本次新增修复。

## 本地打包修正

本地新增 Fn 构建脚本曾向旧 `.app` 副本合并输出，残留的 `com.apple.FinderInfo` 导致严格签名检查失败。公开参考脚本改为重新创建自身的旧构建产物，并在最终输出位置再次检查签名。上游原来的 `build-app.sh` 已经删除旧产物后再复制，因此这属于新增 Fn 脚本的修正，不报告为上游已有打包 bug。公开分支也阻止误用上游脚本以旧应用签名标识构建 Fn 实验包。
