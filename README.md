# DoubaoVoiceBridge（远控听写）

一个轻量的 macOS 菜单栏工具，通过 UU 远程把本机的**语音文字和截图**粘贴到另一台 Mac 的输入框。适用于 MacBook、Mac mini 等 Mac 之间的远程输入。

- **语音**：在 UU 远控窗口中，按住左 `Control` 说话，松开后自动粘贴识别文字。
- **截图**：在本机按 `Option + Shift + S` 框选，完成后自动切回 UU，等待图片同步并粘贴。
- **只粘贴，不发送**：不会自动按回车，也不会点击聊天应用的发送按钮。

> 本项目是非官方的个人自动化工具，与豆包、字节跳动、UU 远控或网易没有隶属、合作或授权关系。相关名称与商标归各自权利人所有。

## 下载与安装

在 [Releases](https://github.com/yupeng316888-create/DoubaoVoiceBridge/releases) 下载应用压缩包，解压后将“远控听写.app”放入“应用程序”目录，再打开。

v2.4.1 提供包含 Apple Silicon 和 Intel 架构的通用应用。当前真实远控验收在 Apple Silicon Mac mini 上完成；Intel 已完成构建验证，尚未在 Intel 硬件上实测。应用采用 ad-hoc 签名，未使用 Apple Developer ID 签名，也未经过公证。

### 运行要求与权限

- macOS 13 或更高版本；MacBook、Mac mini 均可作为控制端。
- 两台 Mac 已通过 UU 远程连接，且可以同步剪贴板。
- 语音功能需要豆包语音输入法，语音快捷键设为左 `Control`，本机有可用麦克风。
- 远端输入框必须支持对应内容；图片粘贴需要支持图片附件的编辑器。

在“系统设置 → 隐私与安全性”中为**远控听写**开启：

| 权限 | 用途 |
| --- | --- |
| 辅助功能 | 识别 UU 目标窗口、切回窗口并执行粘贴 |
| 输入监控 | 识别长按左 Control |
| 录屏与系统录音（部分系统称为“屏幕录制”） | 截取本机选定区域，仅截图功能需要 |

如果权限列表中没有“远控听写”，可点击列表下方的“+”，选择“应用程序”里的“远控听写.app”。

麦克风权限授予**豆包语音输入法**；本工具本身不录音。开启录屏权限后，若系统退出了应用，请从“应用程序”重新打开“远控听写”，否则快捷键不会工作。

## 语音输入

1. 在 UU 中点好远端输入框，保持 UU 远控窗口在前台。
2. 按住左 `Control`，在弹出的本机听写框中说话。
3. 松开按键。工具等待豆包提交最终文字，再通过 UU 粘贴到原远控窗口。

只有 UU 在前台且左 Control 持续按住超过阈值时才进入听写。快速的 `Control-C` 等组合键仍保持原行为。

## 截图输入

1. 在 UU 的远端画面里，先点好一个支持图片的输入框。
2. 回到本机要截取的窗口，按 `Option + Shift + S`（`⌥⇧S`）。
3. 拖动框选区域并松开鼠标；按 `Esc` 可取消。
4. 工具自动切回原 UU 远控窗口，通常等待约 **10 秒**，较大图片最多等待 **15 秒**后执行一次粘贴。消息保留为草稿，由你决定何时发送。

截图传送期间请等待完成，不要切换目标窗口或复制其他内容。截图与本工具的听写任务不会同时操作剪贴板。

也可以从菜单栏“远控听写”打开截图工具，使用“开始截图”“粘贴剪贴板中的图片”“重新粘贴上一张截图”。在访达重新打开应用同样会显示工具窗口。

成功执行粘贴后，**新截图会保留在剪贴板中**；不会定时用旧内容覆盖图片。若远端未显示附件，先确认输入框是否支持图片、焦点是否正确，再手动粘贴或从截图工具重试；不要在已有附件时重复重试。

### 常见问题

- **快捷键没有反应**：确认应用仍在运行；授权后可能需要重新打开。快捷键被占用时可用菜单里的“开始截图”。
- **提示缺少录屏权限**：开启远控听写的录屏权限，再重新打开应用。截图失败不会再被一律显示成“用户取消”。
- **截图有了，远端没出现**：网络和 UU 同步速度会影响结果。等待图片同步，检查远端输入框；本工具无法取得远端编辑器接收成功的回执。
- **焦点或剪贴板变化**：本次自动粘贴会取消，以免粘到错误窗口或覆盖刚复制的内容。
- **多个远控窗口**：优先使用 UU 当前聚焦的远控屏幕；无法确定唯一目标时不自动选择。请先打开预期的远控屏幕。
- **大图或剪贴板过大**：PNG 最大 16 MiB、最多 3200 万像素；原剪贴板无法在 16 MiB 内备份时，本次不会覆盖它。缩小截图区域，或先处理过大的剪贴板内容。

## 工作原理与数据处理

- 语音识别由本机豆包输入法完成；工具使用临时输入框接收最终文字。
- 截图使用 macOS 系统框选，临时图片读入后清理；最后一张截图保留在进程内存中供重试。
- 通过本机剪贴板交给 UU 同步；发送前检查原 UU 进程、窗口和剪贴板是否仍匹配。
- 仅发出完整的 Command-V 按键序列，不发送 Return。
- 语音沿用原有剪贴板恢复行为；截图成功后保留最新图片，取消或失败时仅在仍持有原剪贴板代数的情况下恢复备份。
- 不保存听写正文，不内置账号、远端地址或网络上传接口。语音服务和跨设备传输分别由豆包输入法及 UU 远程负责；粘贴图片后，目标应用自身可能按其规则上传附件。

UU 通过 Bundle ID `com.netease.uuremote` 识别。应用标识、输入法快捷键或相关软件行为变化时，可能需要适配。当前版本保留左 Control 语音方式，没有引入自定义语音快捷键。

## 从源码构建

需要 Xcode Command Line Tools 和 Swift 5.9 或更高版本。

```bash
git clone https://github.com/yupeng316888-create/DoubaoVoiceBridge.git
cd DoubaoVoiceBridge
./scripts/build-app.sh
open dist
```

构建脚本分别编译 Intel 与 Apple Silicon，再生成通用二进制 `dist/远控听写.app`，进行 ad-hoc 签名、严格签名检查、自检和诊断。

## 测试与验证范围

```bash
swift run DoubaoVoiceBridge --self-test
swift run DoubaoVoiceBridge --diagnostics
```

内置自检覆盖长按判定、输入法事件路由与监听顺序、识别稳定等待、完整粘贴按键序列、延迟配置、听写框布局，以及图片传送的窗口／剪贴板变化保护。

v2.4.1 已由维护者在两台 Mac mini 的 UU 连接中实际验证：左 Control 语音输入、本机框选截图、远端图片自动进入输入框且不发送。不同网络、所有远端编辑器、Intel 硬件及多个远控窗口组合未全部实测。测试通过不代表每次远端接收均有自动回执。
